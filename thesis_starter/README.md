# 出院用药预测研究代码入门

这套代码把导读里的四种药、患者划分和四组实验连成一条可以运行的流程。病例和药物都是虚构的。你可以先看终端输出，再在对应函数里逐步核对数据怎样流动。 [逐章导读](../docs/MASTER_THESIS_BLUEPRINT_READING_GUIDE.md) · [研究蓝图](../docs/MASTER_THESIS_RESEARCH_BLUEPRINT.md)

## 在当前工作区运行

用 PowerShell 在项目根目录运行以下命令。建议使用 Python 3.11 或以上版本。这次在 Python 3.14.3 上验证，演示仅用标准库。

~~~powershell
python -X utf8 -B -m thesis_starter
~~~

`-X utf8` 让命令在 Windows 上按 UTF-8 输出，`-B` 省去生成 Python 字节码缓存。数据由程序在内存里构造，结果会打印到终端。

## 为什么先写这些代码

| 研究环节 | 现在可运行的部分 | 与正式实验的衔接 |
| --- | --- | --- |
| 数据处理与跨队列划分 | 自定义教学记录、按患者留出、嵌套抽样、严格共病筛选、缺失与空标签区分。 | 先取得授权数据，核对真实字段、主诊断顺序、处方抄录和药名映射，再接入实际的数据适配器。 |
| 药物编码 | 用导读的一维数字和固定码本逐级选择、计算残差、补消歧后缀，并用随机种子置换整条路径。 | 用获准目录文本训练蓝图中的向量量化编码器，输出相同形式的「药名 → 编号」映射，之后检查 ATC 一致性和碰撞。 |
| 约束生成 | 词典树给出每一步允许的 token。同一套规则用于训练目标、预测和反查。 | 正式模型接入时，Qwen 负责给 token 打分，词典树继续负责合法性。届时核对语言模型的 token ID、排序、停止符和训练掩码。 |
| 基线与生成模型 | 源组频率、按诊断频率、历史药名复制；另有一个从合成文本学习的下一步计数模型。 | 真实文本先跑字符 TF–IDF 多标签基线，再尝试冻结文本向量或 Qwen/LoRA。 |
| 评估与统计 | 按就诊计算 Jaccard/F1，计算四组的增益差与最终分差，并按患者重抽计算区间。 | 复用集合评分与配对抽样思路。蓝图的正式协议还需要锁定真实测试划分、在多个配对种子下运行，并汇总预测与不确定性。 |

先把数据和评分接通有两个好处。你可以在很短时间内看到完整结果。之后如果语言模型给出异常分数，你也有办法分别排查患者划分、编号、解码和计分。

## 第一遍 对照导读第 7–8 章看药物编号

~~~powershell
python -X utf8 -B -m thesis_starter ids
~~~

按下面的顺序读代码。

1. 打开 [ids.py](ids.py) 的 `quantize()`。代码用 `min()` 选择离当前残差最近的代表值，再相减。例如 C 的起始值 116，三步剩下 36、6、−4，选择编号 `(2,9,1)`。
2. 看 `build_ids()`。A 和 B 都选到 `(2,7,4)`，按药名顺序分别加 0、1。`permute_ids()` 则把整条路径重新分给各药。你可以核对两列 ID 的集合相同，但某条 ID 指向的药会变。
3. 打开 [decoding.py](decoding.py) 的 `CatalogDecoder`。`serialize()` 把药集写成固定顺序。`allowed()` 查当前前缀可接哪些 token，`advance()` 推进一步，在到达叶子时记录药名。
4. 对照终端中 `{A,C}` 的九步日志。走完 `(2,7,4,0)` 时记下 A，回到词典树根，从排名更后的药里继续。开始一条药物路径后，必须走到叶子才能再次选择 `<STOP>`。在根部可直接停止，因此空集合也有合法写法。

导读里的 B/D 互换用来说明置换原理。代码用 `--seed` 随机重排整个目录，因此屏幕上的置换可以和纸上的示例不同。四段中的数字按其所在位置理解。接入正式语言模型时，需要为每一层落实独立的 token 编号。

## 第二遍 对照导读第 5 和第 8 章看患者划分

~~~powershell
python -X utf8 -B -m thesis_starter split --k 32
python -X utf8 -B -m thesis_starter split --strict --k 64
~~~

在 [data.py](data.py) 中，`synthetic_visits()` 生成一批有重复住院和共病的虚构记录。`make_split()` 先把同一患者的全部记录放在一起，再判定哪些患者曾有目标主诊断，最后选取每侧有标签且符合诊断的就诊。默认示例有 128 位有标签目标患者，48 人留作测试，80 人进入适配候选池。目标测试共有 49 次就诊，因为有一位患者有两次符合条件的住院。

- P07 曾有目标主诊断，所以他的另一次源组就诊也退出源训练。代码用全部就诊判断这一点，包括某次缺少标签的记录。
- P08 只有目标次诊断。默认分析允许他留在源训练，严格分析排除他。两次命令的目标测试仍是同一批人，源训练从 216 人减少到 215 人。
- `support(k)` 沿候选池的固定患者顺序取前 `k` 人，再保留这批患者的全部合格目标就诊。在同一划分里，8 人适配组会包含在 16 人组里。

非目标患者在这个入门版按其第一条合格就诊的主诊断分层。正式数据里要先核验诊断次序、交叉人群和样本容量。教学 CLI 的 `--seed` 同时控制划分、置换和重抽样。研究运行要保存独立的固定划分清单，再明确区分适配抽样、置换与训练的随机种子。

如果你想练习读取 JSON，`read_visits()` 接受下面这种**教学格式**的 UTF-8 文件，顶层是记录数组。主诊断、次诊断和病史字段中的字符串按已经整理好的标签处理。

~~~json
[
  {
    "patient_id": "example-p1",
    "visit_id": "example-v1",
    "primary_diagnosis": "目标组",
    "text": "线索甲 记录完整",
    "secondary_diagnoses": [],
    "history_diagnoses": [],
    "medication_mentions": ["B"],
    "discharge_medications": ["A", "C"]
  }
]
~~~

`read_visits("你的教学文件.json")` 返回 `Visit` 对象。`discharge_medications: []` 表示已确认空处方，`null` 或缺省表示标签未知。CLI 默认生成内存数据即可运行。手写记录可以在 Python 中交给 `make_split()` 或 `evaluate()`。只有一两条记录时，适合先逐条观察字段或练评分。

## 第三遍 对照导读第 11.1 节看基线

~~~powershell
python -X utf8 -B -m thesis_starter baselines
~~~

在 [baselines.py](baselines.py) 中，`FrequencyBaseline.fit()` 数源训练的药名标签。预测时可以取全局最常见的两种，也可以按主诊断取这个诊断里的高频药。本例训练源组没有目标主诊断，所以按诊断法在目标组会回退到全局频率。只复制历史药名的 `mention_copy()` 使用合成记录里独立提供的 `medication_mentions`，并限制到目录内。你可以把这三种办法理解成「猜常见项」和「照着历史线索猜」的参照。

## 第四遍 对照导读第 10–11 章完成四组实验

~~~powershell
python -X utf8 -B -m thesis_starter transfer --k 32 --replicates 2000
python -X utf8 -B -m thesis_starter transfer --k 0
~~~

[model.py](model.py) 里的 `PrefixCountModel` 是用来读懂训练和预测的计数模型。训练时，`learn()` 沿正确答案行走，记录「某个文本提示出现时，在当前前缀之后通常会接什么 token」。源码把当前前缀和已完成药物数量一起记作上下文。预测时，`token_probabilities()` 在合法选项上把计数加 1，再除以总数得到概率，`predict()` 用束搜索尝试多条生成路径。这样你可以在代码里看见「训练沿正确答案」「推断沿自己选的答案」这两步。正式 Qwen/LoRA 的模型参数学习由后续实现负责。

[入口脚本](__main__.py) 为两套编号分别训练两条路线。`target` 从空计数开始，只读目标适配患者。`transfer` 先累计源组计数，再读同一批目标患者。测试时，模型只读允许的病历文本。两种编号共用样本、词典树形状和搜索配置。`k=0` 时只运行两个源模型并打印直接分差。

### 先核对手算，再读代码算出的结果

[evaluation.py](evaluation.py) 的 `score_visit()` 会复算 `{A,C}` 对 `{B,C,D}` 的 Jaccard 0.25、F1 0.40，总分 0.325。`transfer_effects()` 用导读里假设的四个数字重现增益差 +0.04、最终分差 −0.02。

默认种子 42 和 `k=32` 下，下面才是本次**合成计数模型现场运行**所得的平均 Jaccard。

| 编号 | 只用目标组 | 先源后目标 | 源训练带来的变化 |
| --- | ---: | ---: | ---: |
| 固定残差 ID | 0.901 | 0.741 | −0.160 |
| 同树置换 ID | 0.799 | 0.619 | −0.180 |

两组在加入源训练后都下降。因为固定残差组下降得稍少，所以差上再相减仍得到 +0.020。最终直接比较 0.741 和 0.619，得到约 +0.122。计数模型直接累加两组记录，人数较多的源队列可能留下更多计数，使少量目标病例难以改变预测。这个演示说明为什么要同时看两种差值。真实病历上的处方复现表现需要在获准数据上按正式协议测量。

`paired_bootstrap()` 每轮按患者重抽，同一患者的多次就诊一起进入重抽样，四个实验组都用这一轮的同一批患者来算差值。复现时可以看到，在 2,000 次重抽样下，这个示例的增益差区间约为 [−0.102, +0.137]，跨过 0。改变 `k` 或 `--seed` 后，先检查使用的患者与置换，再解释分数变化。

## 用测试检验你的理解

~~~powershell
python -X utf8 -B -m unittest discover -s thesis_starter/tests -v
~~~

`test_data.py` 检查同一患者的多次就诊是否跨组。`test_ids_decoding.py` 让四种药的全部 16 种集合在两套编号下走一遍往返，并检查半路停止、逆序与重复。`test_evaluation.py` 检查缺失金标、空集合和患者有多次就诊时的统计。`test_model.py` 检查合法下一步的概率、计数模型的生成结果和遇到无效标签时的处理。
